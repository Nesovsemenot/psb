# ПСБ · Умный поиск — отчёт по конверсиям

Автоматизация сбора данных из Яндекс Метрики для оценки эффективности умного поиска.

## Что считает

Для каждой страницы на `psbank.ru`, где настроена цель оформления заявки,
собирается:

- количество событий / посетителей за период (всего)
- количество событий / посетителей из переходов умного поиска
  (фильтр `utm_source=ai_search`)
- доля ИИ-поиска в конверсиях

Учитываются две группы целей:

1. **JS-события MSB_prod** — отправки форм на лендингах МСБ
   (РКО, Эквайринг, Регбиз, Кредиты, Депозиты, ВЭД и т.д.)
2. **Цель 609847539** — переходы на `ib.psbank.ru/store/products/`
   (заявки на розничные продукты через интернет-банк)

## Структура

## Запуск

### Разовая настройка

```bash
pip3 install --break-system-packages openpyxl
export YM_TOKEN="y0__..."     # OAuth-токен Яндекс Метрики
```

Токен получается на [oauth.yandex.ru](https://oauth.yandex.ru) с правом
`metrika:read`. Если токен утечёт — отзывается в один клик там же.

Положи `mapping.xlsx` в корень проекта. Это выгрузка гугл-дока «Разметка»
(Файл → Скачать → Microsoft Excel). Листы: РКО, Эквайринг, Депозиты, ЛП,
Кредиты, Регбиз, Международные платежи, OPC, Articles, Предпринимателям.

### Обычный запуск

```bash
python3 collect_events.py        # 1-3 минуты, устойчив к обрывам сети
python3 build_events_xlsx.py     # моментально
open psb_events_with_ai.xlsx
```

### Смена периода

В `collect_events.py` поменять `DATE1` и `DATE2`, удалить `cache_events.json`,
запустить оба скрипта заново.

## Что было сделано по пути (ключевые решения)

### 1. Правильные имена атрибутов event_params API

Таблица `event_params` в UI Метрики ходит в недокументированный endpoint.
Правильные имена атрибутов нашлись через `preset=goal_params`:

- `ym:ep:actionGoal` — название цели (JS Event)
- `ym:ep:eventParamsLevel1..5` — уровни параметров
- `ym:ep:eventsNumber` — события
- `ym:ep:users` — посетители

### 2. Кросс-уровневые фильтры

Работает связка `AND` между атрибутами разных уровней:
`ym:ep:eventParamsLevel1=~'MSB_prod' AND ym:s:UTMSource=~'ai_'`.

В UI такое выдаёт «Условия, которые нельзя применить», в API — отрабатывает.

### 3. endURL для цели перехода на ib.psbank

Для 609847539 (переход на другой домен) правильный атрибут —
`ym:s:endURL` (последняя страница на `psbank.ru` перед уходом),
а не `startURL` (первая страница визита).

### 4. Дедупликация по (L2, L3)

Одно JS-событие попадает в несколько целей одновременно
(«МСБ // Весь РКО», «МСБ // Все ЛП», «Любая цель || AI Search» и т.д.
на одну и ту же отправку формы `lp/smb/rko`). Для реального числа
заявок берётся максимум по целям, а не сумма.

### 5. Фильтрация строк без маппинга

Из `event_params` приходят и клики по кнопкам/карусели (L3 с кириллицей),
их отбрасываем — к оформлению заявки они не относятся. Остаются только
строки с найденным соответствием URL → цель в маппинге.

## Что НЕ в git

- `YM_TOKEN` — только через переменную окружения
- `cache_events.json` — промежуточный кэш, пересобирается скриптом
- `psb_events_with_ai.xlsx` — итоговый отчёт, генерируется
- `mapping.xlsx` — приватная выгрузка из внутреннего гугл-дока

Все эти файлы в `.gitignore`.


## Ограничения

- Фильтр умного поиска работает по `utm_source=ai_search`. Если на фронте
  метка не ставится, конверсия будет занижена
- Маппинг URL → цель не покрывает глубокие подстраницы и клики по кнопкам.
  Для полного покрытия нужно дополнить гугл-док «Разметка»
- Цели по розничным продуктам в счётчике 18882175 почти отсутствуют —
  основной канал измерения эффективности для розницы — цель 609847539
  (переходы в интернет-банк)
